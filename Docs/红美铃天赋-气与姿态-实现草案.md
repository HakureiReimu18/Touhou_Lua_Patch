# 红美铃天赋「气与姿态」Lua/CS 实现草案

> 状态：草案 v2，待评审。仅覆盖 XML 做不到的部分；其余一律留在 XML。

## 0. 总览：职责划分

| 效果 | 实现方式 |
|---|---|
| 基础属性（远程/近战速度、伤害、生命值、技能获取速度） | XML 天赋 |
| 「气」数值（0~100） | affliction `Meiling_Qi` 存储 + 服务端 Lua 驱动增减 |
| 气衍生的近战伤害/攻速/眩晕抗性加成 | **XML**：affliction 的 stattype/抗性效果随 `Meiling_Qi` 强度缩放，Lua 不碰 |
| 姿态效果（蓄势/护身/全力的常驻增减） | **XML**：写在三个姿态 affliction 上（stattype、抗性、承伤减免等） |
| 屏幕上的气条与百分比 | 客户端 C# Harmony 绘制（参考 `BondGui.cs`） |
| 姿态切换：装束按钮 → Lua hook，含 10 秒冷却与互斥清理 | 装束按钮（XML，沿用秦心/恋/小恶魔的做法）+ 服务端 Lua 逻辑 |
| 蓄势每秒 +1% / 全力每秒 -1% 的气增减 | 服务端 Lua `think` 节流 |
| 蓄势姿态下造成伤害/受到伤害获得气 | 服务端 Lua（按伤害量折算，设上下限） |
| 全力专属武器 20% 概率 50% 额外伤害 + 消耗 2% 气 | 服务端 Lua `ApplyAttack` 补丁（参考 `Touhou_Magic_Weapon_Bonus.lua`） |

## 1. 数据层：affliction 承载「气」和「姿态」

沿用 `Jyoon_Wealth_Talent.lua` 的模式，所有动态状态用 affliction 强度表示：

- **联机同步免费**：affliction 强度随 CharacterHealth 自动同步给所有客户端，HUD 直接本地读，无需自建网络同步气数值。
- **死亡/脱装自动清理**：affliction 设 duration，脱离条件后自然消失。
- **调试方便**：健康界面里可读，排查问题时有用。

拟新增 affliction（定义放本体模组的 Afflictions.xml）：

| Identifier | 含义 | 强度语义 | XML 侧职责 |
|---|---|---|---|
| `Meiling_Qi` | 气 | 强度 0~100，即百分比数值 | stattype/抗性效果按强度缩放：近战伤害最多 +20%、近战攻速最多 +10%、眩晕抗性最多 +15% |
| `Meiling_Stance_Charge` | 蓄势 | 有=当前姿态 | 无常驻属性（获气逻辑在 Lua） |
| `Meiling_Stance_Guard` | 护身 | 有=当前姿态 | 承伤 -25%、近战伤害 +10% |
| `Meiling_Stance_Allout` | 全力 | 有=当前姿态 | 近战伤害 +30%、近战攻速 +10% |

三个姿态 affliction 互斥，同一时刻有且只有一个（服务端 Lua 保证）。用三个独立 affliction 而非一个强度编码，是为了 XML 侧写 stattype/抗性效果以及装束/联动判断时直观。

注意点（`Jyoon_Wealth_Talent.lua` 已踩过）：`ApplyAffliction` 会按 `100/MaxVitality` 缩放强度，施加后必须立即把 `Strength` 写回目标值，直接复用该文件的 `set_affliction` 写法。

## 2. 姿态切换：装束按钮 → Lua hook

**不做独立热键**。姿态切换按钮做在装束上（沿用秦心/恋/小恶魔的现有做法），这样现有快捷键系统里「装束按钮」的键位配置直接可用，无需新增配置项。

- **XML 侧**：装束上加三个按钮（蓄势/护身/全力），各发一个 StatusEffect 触发 Lua hook（触发方式照抄现有角色装束按钮的实现）。
- **Lua 侧（服务端权威）**：收到 hook 后：
  1. 校验角色拥有天赋 `MeilingTalent`；
  2. 校验冷却：每角色记录上次切换时刻，间隔 < 10 秒则拒绝（可选回执提示「冷却中 X 秒」，联机走一条 `TLE_ML_DENY` 消息或直接在 HUD 上由客户端本地计时显示）；
  3. 清除三个姿态 affliction，施加目标姿态 affliction。
- **巡回开始默认蓄势**：`Hook.Add("roundStart", ...)` 对所有天赋角色清姿态、上 `Meiling_Stance_Charge`；中途获得天赋/重生时兜底同样处理。**气不归零**，跨巡回保留。
- **全力气耗尽不自动切姿态**，由玩家手动切换（每秒 -1% 的消耗照常执行，气停留在 0）。

## 3. 气的增减循环（服务端 Lua）

新文件 `Lua/Scripts/Sever/Meiling_Qi_Talent.lua`，`think` hook 节流每秒结算一次：

- 遍历 `Character.CharacterList`，筛出拥有天赋 `MeilingTalent` 的角色（判定照女苑脚本：`HasTalent` + 装束检测，如需绑定装束）。
- **蓄势**：每秒 +1% 气。
- **护身**：气不变。
- **全力**：每秒 -1% 气，触底停 0，不自动切姿态。
- 全局 clamp 0~100。

**战斗中获得气**（仅蓄势姿态）：

- 按**伤害量**折算，避免高频低伤刷气和低频高伤爆气，每次获气设上下限：
  - 造成伤害：`Hook.Patch("Barotrauma.Character", "ApplyAttack", ...)` After 补丁读 `ptable["attacker"]` 与最终伤害（`Touhou_Magic_Weapon_Bonus.lua` 在用同一补丁点，可共存）。
  - 受到伤害：`Hook.Add("character.applyDamage", ...)`（模式见 `Touhou_Hisoutensoku_Amor.lua`），按实际损失生命折算。
  - 折算比例与上下限数值待平衡，草案占位：获气 = clamp(伤害 / 最大生命 × K, 单次下限, 单次上限)。
- 造成/受到伤害的获气是否同比例、是否需要不同系数，待平衡。

## 4. HUD：屏幕上的气条（客户端 C#）

纯 Lua 没有稳定的屏幕绘制入口，建议直接用 C# Harmony，本 mod 已有完整先例（`BondGui.cs` 用 Harmony 补丁 `GameMain.Update` 驱动 GUI）。

拟新增 `CSharp/Shared/MeilingQiHud.cs`（`#if CLIENT`）：

- 补丁 HUD 绘制方法 Postfix（具体目标方法待验证，见 §6），在屏幕上常驻绘制。
- 每帧读取 `Character.Controlled` 的 `Meiling_Qi` 强度与当前姿态 affliction——**affliction 强度本身已同步，无需任何网络消息**。
- 绘制内容：
  - 气进度条（0~100），颜色随姿态（蓄势绿/护身蓝/全力红）；
  - 百分比数字；
  - 当前姿态名称文本；
  - 切换冷却剩余时间（客户端从发请求时刻本地起算即可）。
- 位置：先写死在生命条附近或屏幕下缘，后续再考虑配置项。
- 仅本地角色拥有天赋时显示。

备选：若当前游戏版本的 Lua API 有可用 HUD 绘制 hook 则改用客户端 Lua，减少 C# 侧维护；实现前先验证。

## 5. 全力姿态：专属武器触发 + 耗气（服务端 Lua）

`ApplyAttack` Before 补丁，与魔法武器加成并列：

1. 攻击者有 `Meiling_Stance_Allout` 且 `Meiling_Qi > 0`；
2. 武器判定：`attack.SourceItem`（或双手物品）带专属标签（如 `Meiling_Exclusive`），写法照 `get_weapon_level_config` 模式；
3. 掷 20%：命中则 `DamageMultiplier × 1.5`，**在同一次攻击结算内**把 `Meiling_Qi` 强度 -2——消耗写在触发点内部，天然原子，无需额外同步；
4. 随机数在服务端执行；补丁加 `if CLIENT and not Game.IsSingleplayer then return end` 守卫，防联机各端重复结算。

## 8. 已定设计结论

- 全力气耗尽**不**自动退回蓄势，玩家手动切换。
- 巡回开始气**不**归零，跨巡回保留；姿态重置为蓄势。
- 战斗获气按伤害量折算，每次获气设上下限，防止高频低伤刷气与低频高伤爆气。
- 姿态切换输入走装束按钮，复用现有快捷键系统的装束按钮键位配置，不新增热键项。
- 气衍生的属性加成与姿态常驻效果全部由 XML affliction 承担，Lua 只管状态流转和数值增减。

## 与草案 v2 的差异

1. **姿态切换是纯 XML，Lua 不参与**：spike 发现装束按钮没有直达 Lua 的回调机制，而秦心/小恶魔的「信号 affliction + Conditional 冷却 + ReduceAffliction 互斥」模式已能完整覆盖需求（10 秒冷却、互斥、快捷键系统的装束按钮键位自动可用），故不引入 Lua 轮询。
2. **标识符按本体模组惯例改为 `Hong_Meirin_*`**（草案中的 `Meiling_*` 废弃）：
   - `Hong_Meirin_Qi`（气，0~100）、`Hong_Meirin_Stance_Charge/Guard/Allout`（姿态，共用 type `Hong_Meirin_Stance` 供 ReduceAffliction 互斥）、`Hong_Meirin_Stance_CD`（切换冷却，强度=剩余秒数，strengthchange -1）。
   - 专属武器标签 `Hong_Meirin_Exclusive`（武器 XML 尚不存在，打上该 tag 即接入全力触发）。
3. **姿态 affliction 的 Effect 用 `minstrength="1"`**：StatValue 在强度窗口内按 `Lerp(minvalue, maxvalue, InverseLerp(...))` 取值，强度 0 时仍取 minvalue，固定值效果不会消失；`minstrength=1` 使强度归零后 GetViableEffect 返回空、效果彻底失效。气的 Effect 因 minvalue 全为 0，保持 `minstrength="0"`。
4. **承伤 -25% 用 `resistancefor="damage,burn,bleeding"`**：StatTypes 没有承伤乘子，也没有 StunResistance（眩晕抗性一律走 `resistancefor="stun"`）。
5. **战斗获气用 `ApplyAttack` After 补丁**（instance=受击者、attacker=攻击者，可双方判定敌我），伤害量取 `attack.GetTotalCharacterDamage()` 估算。无攻击者的环境伤害不给气。
6. **全力触发不还原 DamageMultiplier**：与 Touhou_Magic_Weapon_Bonus 的备份/还原模式共存的关键是加载顺序——本脚本必须在它之后 dofile（init.lua 已注明），且同一攻击实例只掷一次 20%（弱键表按 attack 去重，一次挥击命中多肢体不重复判定/耗气）。
7. **HUD 补丁点是 `CharacterHUD.Draw` Postfix**（仿 InnerClothesPortraitMod），直接读本地 affliction 强度，零网络消息。HUD 只在操控美铃本人时显示。
8. **巡回开始强制回蓄势**：姿态 affliction 无 duration 会跨巡回残留，故 `roundStart` hook 对所有穿着装束的角色清姿态并上「蓄势」；think 里的无姿态兜底（每 0.5s）覆盖重生/中途穿上等其余情况。气跨巡回保留（不归零），但脱下装束会清零（与女苑天赋的脱装清理一致）。

# 实现记录（v4，2026-10-02，bug 修复 + 通用进度条系统）

## Bug 修复

1. **姿态切换失败（永远蓄势）**：根因是 StatusEffect 的子元素按类别执行——所有 `Affliction` 施加完后才执行 `ReduceAffliction`（StatusEffect.cs 源码确认），按 type 互斥清理会把刚施加的新姿态一并清掉，Lua 无姿态兜底随后补回蓄势。修复：按钮改为按 identifier 只清**另外两个**姿态（`ReduceAffliction identifier="..."`），顺序无关。
2. **暂停时气仍增长**：think 钩子在暂停时照常触发。修复：`Meiling_Qi_Talent.lua` 的 think 入口加 `is_game_paused()` 守卫（pcall 读 `GameMain.Instance.Paused`，读不到时放行）。

## 通用 HUD affliction 进度条系统

`MeilingQiHud.cs` 已删除，由 `CSharp/Client/HudAfflictionBars.cs` 取代：

- **配置驱动**：`Config/hud_bars.xml` 里每行 `<Bar affliction="..." name="..." color="R,G,B" maxstrength="..."/>` 即一条竖条；可选 `<State>`（姿态类状态，强度≥1 时替换标题与颜色）与 `<Extra>`（附加文本行，如切换冷却）。新增机制（爱丽丝人偶能量、咲夜血之时计、厄运缠身等）只需加一行。
- **渲染**：补丁 `CharacterHUD.Draw` Postfix，屏幕右侧中间竖条横排（配置序靠右），自下而上填充；标题在条上方居中，Extra 在条下方。不画 `GUI.DrawProgressBar`（其内部是翻转 Y 坐标，屏幕坐标系下会画到屏幕外）。
- **玩家设置**：「东方模组设置」主菜单新增「进度条设置」入口（Lua 写 `open_hudbar_settings=1` 标记，C# 轮询开窗，仿 BondSettingsGui）。窗口内可调全局缩放（0.5~2.0）、每条的开/关与 RGB 颜色、单条重置默认。用户改动存存档目录 `TouhouHudBarsConfig.txt`（覆盖层，模组更新不丢；默认 XML 与用户配置均 2 秒 mtime 热更新）。

## 踩坑备忘

- `GUIScrollBar` 的滚动属性是 `BarScroll`（0~1），不是 `Scroll`；值换算默认 `Lerp(Range.X, Range.Y, BarScroll)`。
- `GUIFrame` 构造第二参 `style` 传 null 即纯色块（颜色预览用）。
- `GUIStyle.Font.MeasureString(string)` 可直接量文字尺寸。

# 实现记录（v5，2026-10-02，跨模组兼容 + 多条显示方案）

## 跨模组兼容

- 约定的配置文件路径：**任何内容包**（包括纯 XML 模组）在自己包里放 `Config/hud_bars.xml` 即被自动加载。渲染侧每 2 秒扫描 `ContentPackageManager.EnabledPackages.Regular` 里所有包的该路径，新文件出现/内容变化都会热重载。
- 加载顺序：本 Lua 补丁优先，其余内容包随后；同一 affliction id 重复登记时先加载者生效，重复定义跳过。
- 玩家覆盖层（`TouhouHudBarsConfig.txt`）按 affliction id 生效，对其他模组登记的条同样可调开关与颜色。

## 多条显示方案

「编组居中」：所有竖条围绕屏幕右缘内侧 70px（×缩放）的一条锚线对称展开，每条占 96px 槽位，条在槽内居中，标题在条上方对条居中，附加行在条下方对条居中。一条时居中于锚线；两条时对称分布两侧；更多条自然向屏幕中部排开。配置/加载顺序从左到右。

## 其他模组接入示例

在对方模组根目录放 `Config/hud_bars.xml`：

```xml
<HudBars>
  <Bar affliction="SomeMod_Energy" name="能量" color="120,200,255" maxstrength="100" enabled="true"/>
</HudBars>
```

无需引用本补丁的任何程序集或 Lua 接口。

# 实现记录（v6，2026-10-02，设置窗扩展：位置/偏移/条长）

# 实现记录（v12，2026-10-03，多人模式页面崩溃修复）

## 根因

多人客户端的 Lua 上下文里 **`Timing` 是 nil**（单机/编辑器有）。绑定/耐久页的「拒绝反馈」用了 `Timing.TotalTime`，页面构建在该行崩溃，被 `pcall(open_menu)` 静默吞掉 → 崩溃点之后的保存/重置/返回/关闭按钮全部没建出来，布局也因缺少子项而错乱。这就是"多人模式没有文本框/按钮、编辑器里正常"的原因。

## 修复

- 拒绝反馈的新鲜度判断移到 C# 侧（`BondSettingsBridge`：状态快照里的 `denied` 只写 10 秒内的，过期自动重写清空）；Lua 只看 `denied` 非空。
- 两个自研页面（bondsettings/condloss/hudbars）的构建主体全部用 `xpcall` 包住：构建出错在页面上显示错误文本并写 `page_error.txt`，杜绝静默失败。
- 文本框构造定为 `GUI.CreateTextBoxWithPlaceholder`（装束锁定页验证过的路径）。

## 排障方法论备忘（下次别浪费时间）

1. 涉及游戏机制的修改，先小步验证再铺开（这次文本框问题来回多轮）。
2. `pcall(open_menu)` 这类全吞的容错让构建错误完全不可见——页面构建一律 xpcall + 错误上屏。
3. Lua 全局对象在不同上下文（单机/多人客户端/服务器）可用性不同（如 `Timing`），用时先 pcall 探测或挪到 C# 侧。
4. 诊断信息写文件 > 写消息栏（会消失）> print（多人客户端控制台可能不可见）。

# 实现记录（v14，2026-10-05，绑定/耐久设置联机权限放宽）

## 现象与根因

玩家反馈「绑定系统设置里结算间隔最小只能 1 秒」。核对现场文件后确认**代码里没有数值下限**（运行期下限一直是 `Math.Max(SettleInterval, 0.1)`，见 BondDamage.cs）：`TouhouBondRequest.txt` 里 Lua 侧确实写入了 `settleinterval=0.5`，但 `TouhouBondState.txt` / `Config/bond_config.xml` 仍是 1，且 state 的 `deniedat` 正好是保存时刻——即这次修改被服务器回 `NET_DENIED` 拦掉了。

- Lua `bs_hint`（中/英）同步改为「多人模式需要管理员权限（ConsoleCommands）」。

注：该判定在**服务端**执行，联机场景需要服务器侧的 mod 也更新到本版本。
