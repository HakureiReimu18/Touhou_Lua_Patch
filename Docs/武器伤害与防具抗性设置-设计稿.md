## 2. 已核实的技术事实（本机程序集 + 内容实测，2026-10）

## 3. 最终规则：乘什么、不乘什么

### 3.1 伤害倍率（武器组 / 舰炮组通用）

**只乘伤害类 affliction 的 strength**，判定 = `AfflictionPrefab.AfflictionType` ∈ 白名单，默认：

```
{ damage, burn, bleeding, bloodloss }
```

白名单与 identifier 级特例表均可配置（如要把 stun 或某个自定义 aff 纳入，加一行即可）。

覆盖**三个来源，统一规则**：

1. `Attack` 自带 afflictions（Projectile / MeleeWeapon）；
2. `StatusEffect` 主动施加的 afflictions——**仅当效果目标含 `Limb / UseTarget / AllLimbs / LastLimb`**（默认目标集，可配）：
   - 组件级 StatusEffect（Projectile.OnImpact、RepairTool 喷火器等）；
   - **Attack 内嵌的 StatusEffect**（实测存在）；
3. `Explosion`（含嵌套在 StatusEffect 里的）的 afflictions。

### 3.2 穿甲倍率（直击 + 爆炸）

**两种模式二选一生效**（每个分组独立配置）：

| 模式 | 公式 | 中性值（默认，等于不改） | 档位示例 |
|---|---|---|---|
| 加算（默认） | `pen' = base + Δ` | Δ = 0 | LV2 Δ = +0.05 |
| 乘算 | `pen' = base × k` | k = 1 | LV2 k = 1.25 |

最终 `clamp(pen', 0, 1)`——**绝不出现 >1**。原因：`Limb.AddDamage` 对 `DeflectProjectiles` 条目做 `Lerp(v, 1, penetration)`，penetration > 1 会超冲成"负减伤"（比无视护甲还疼）。

作用对象：直击 `Attack.Penetration`，以及爆炸 `Attack.Penetration`（默认跟随同一设置）。

### 3.3 防御倍率（防具组）

`v' = clamp(1 − (1−v) × M, 0, 1)`，**中性值 M = 1（默认，等于不改）**；M=0 = 未穿防具；作用对象 = 该物品 `Wearable.DamageModifiers` 的全部条目（含 probabilitymultiplier 不动）。

### 3.4 明确不乘（本版范围外）

| 项 | 说明 |
|---|---|
| structuredamage / itemdamage / levelwalldamage | 不乘（含舰炮，按作者决定） |
| targetforce / targetimpulse / severlimbsprobability | 不乘 |
| stun / slow / paralysis / debuff 等非伤害 affliction | 不乘（白名单外） |
| 爆炸 range / force | 不乘（"范围轴"整体不做） |
| `RangedWeapon.Penetration` / `WeaponDamageModifier` | 不在补强范围，不动 |

### 3.5 爆炸穿甲：默认开、bug 不修

- **跟随穿甲设置：默认开**（即爆炸的 `Attack.Penetration` 也会被加/乘）。当前因游戏 bug 无实际效果；官方修复后自动生效，维持与滑条语义一致。
- **顺手修复**（转译把 `attack.Penetration` 接进 `Explosion` 伤害链）：属玩法改动，单独开关，**默认关**。
- 配置里两个独立开关：`explosion.followPenetration`（默认 true）、`explosion.fixPenetrationPath`（默认 false）。

### 3.6 与补强补丁的预期差异（有意为之）

- stun 不再随倍率（补强曾 ×1.4~2）；
- structuredamage/itemdamage 不再随倍率（补强动过少数几处）；
- 个别自定义 affliction 的专项增减（如 `Touhou_Lost_Dream` ×0.26、`Touhou_Alice_Magic_Book_Bolt_Effect` ×0.13）不复刻；
- 以上如需复刻：加 identifier 特例表 / 提通道开关，均为配置层改动。

## 4. 采集机制与完整性保障

采集器对分组内每个物品**递归遍历"从物品可达的所有伤害数据点"**，规则只决定乘不乘：

```
物品
├─ 组件（Projectile / MeleeWeapon / RepairTool / Holdable / RangedWeapon / …全类型）
│   ├─ Attack ──────────────→ afflictions
│   │   └─ Attack.StatusEffects ─→ { afflictions, Explosions → Attack }
│   └─ 组件 StatusEffects ───────→ { afflictions, Explosions → Attack }
└─ Wearable（防具组）→ DamageModifiers[*]
```

`damage_dump <identifier|all>` 审计命令：输出每条候选的完整归属链 → affliction type → 判定（乘 / 不乘 + 原因：类型不在白名单 / 目标不符 / 通道关闭）→ 旧值 → 新值。P0 交付后先跑它核对覆盖面（重点：Projectile 内嵌 StatusEffect、爆炸、喷火器、舰炮弹）。

## 5. 架构

### 5.1 实现落点（实际结构，2026-10-05 现状）

命名空间 `Touhou.Damage`，Harmony id `touhou.damage`；插件入口照 `HomingPlugin` / `BondPlugin`：

```
DamageSettings.cs   DamagePlugin : IAssemblyPlugin（Initialize / OnLoadCompleted / Dispose 防 reloadlua 堆叠）
                    DamageConfig（读 Config/damage_settings.xml，跨包合并 + Rules + Tier）
                    DamageScanner / DamageDump（只读审计：damage_dump / damage_probe）
DamageApply.cs      DamageValues（玩家值 ↔ TouhouDamageConfig.txt ↔ 状态快照；联机请求解析/校验/差分）
                    DamagePatcher（Item 构造 postfix + 弱表底值快照 + 状态文件归一，仅权威端应用）
                    DamageDisplay（状态文本工具：剔除 applied.* 后供广播/镜像）
DamageNet.cs        DamageClientState / DamageNet（联机传输，照 BondNet：ILuaCsNetworking 反射收发）
                    DamageChat（聊天公告：反射调 GameServer.SendChatMessage；单机走 CrewManager）
                    DamageBridge（文件桥，照 BondSettingsBridge：请求文件 → 应用/发送；客户端镜像写盘）
Lua/Scripts/Client/Touhou_Mod_Hotkey.lua   设置页（hub 按钮 + 档位 + 滑条/保存/重置；写请求文件 + 只读状态文件）
（另：DamageConfig.AutoCollect 每次启动自动扫描名字含「东方」的内容包，把可补强物品并进分组，见 §12-13）
```

控制台命令：`damage_reload`、`damage_list`、`damage_set <组> <轴> <值>`、`damage_reset`、`damage_apply`、`damage_lv <1|2|3>`、`damage_probe`、`damage_dump`、`damage_rescan`（重扫自动收录）、`damage_item <物品id> <damage|pen> <值> | clear | list`（单件单独调整，见 §12-14）。`set/reset/lv/item` 都会先取快照、改完广播状态+全服公告。

### 5.2 配置与数据文件

| 文件 | 位置 | 职责 |
|---|---|---|
| `Config/damage_settings.xml` | 模组包内 | 分组定义（id/显示名/类型/默认值/穿甲模式/物品清单/tag），随模组分发；其他包同名文件跨包合并（照追踪系统先例） |

### 5.3 UI（Lua）

`Touhou_Mod_Hotkey.lua` 新增页「武器伤害与防具抗性设置」：hub 按钮 → 两栏布局（照进度条设置页）——左列分组，右列参数轴（武器组：伤害滑条 + 穿甲"模式切换 + 滑条"；防具组：防御滑条），带数值显示、精确输入框（照 condloss 页样板）、保存 / 重置。分组与参数轴全部由状态文件驱动，联动模组注册的新分组自动出现。

## 6. 生命周期与防叠加

| 场景 | 行为 |
|---|---|
| 巡回切换 | 船/物品为同一批对象，已乘值天然保留；新生成物品（wreck/站点等）在构造时打补丁 |
| 读档 / 加入 | 物品重建 → 构造钩子按当前配置重打；值不落盘，不会叠加 |
| 新建物品（合成/装填/发射） | 同上；弹药箱 `SpawnItem` 生成的弹体单独成物品 → 单独打补丁 |
| reloadlua（插件重载） | 弱表快照丢失 → 用状态文件里"已应用倍率"做除法归一，绝不越调越强 |
| 玩家改配置 | C# 轮询 mtime → 全量重应用（毫秒级）→ 更新状态文件 → UI 刷新 |

## 8. 联动接口

**现行（已实现，2026-10-06）——XML 配置合并，零代码**：其他模组在自己包的 `Config/damage_settings.xml` 里声明即可（所有启用内容包的同名文件按加载顺序合并；后加载覆盖先加载）：

```xml
<!-- ① 加进已有分组：只写 <Group id>，不写属性 → 保留该组原有名字/类型/默认值 -->
<Group id="exclusive"><Item id="my_bullet"/></Group>
<!-- ② 按 tag 收录（内容加载后展开，新物品带 tag 会自动进来） -->
<Group id="general"><Tag name="my_mod_danmu"/></Group>
<!-- ③ 自建分组（设置页自动出现；默认值请用中性值，强度交给玩家档位/滑条） -->
<Group id="my_mod" label="我的模组武器" kind="weapon" defaultDamage="1.0"
       penetrationMode="add" penetrationValue="0.0">
  <Tier level="2" damage="1.2" penMode="add" penValue="0.05"/>
  <Item id="my_bullet_01"/>
</Group>
<!-- ④ 排除（对显式收录与自动收录都生效） -->
<Exclude id="some_item"/>
```

- 验证：`damage_list` 打印「合并来源」与每组条目数；`damage_probe <id>` 看物品归属；拼错的 id 会在日志告警。
- 完整写法与注意事项见 **`Docs/联动模组兼容说明.md`**（可直接发给联动模组作者）。
- 待定/未实现（如真需要再做）：运行时 `Hook.Call("touhouDamageRegister"/"Bind"/"Unregister"/"Get")` 动态注册/查询——XML 路线已覆盖"写个文件就兼容"，暂不做。
- **内置清单 + 运行时自动收录**：显式清单由 _dev 脚本生成（专属=补强 TouhouWeapon 范围 ∪ 内容 TouhouWeapon.xml 全量、泛用=OtherWeapon 同理、舰炮弹药=符卡弹箱+弹体闭包 等），内容更新后重跑；**另外每次启动会扫描名字含「东方」的模组自动收录**（见 §12-13），所以清单不用频繁维护。

## 9. 联机

- 伤害为服务端权威。
- **v3（已实现，2026-10-05；传输全在 C#）**：按作者决定"走 CS 传输、用现成稳定方案"，照 **`BondNet` / `BondSettingsBridge`** 那套（该通道在作者服务器上有实证：`[绑定] …通过设置窗口修改了绑定配置` 被服务端正常处理）：
  - 文件桥（`DamageBridge`，由插件 `think` 钩子每帧驱动）：
    - 设置页「保存/档位/重置」只写 `TouhouDamageRequest.txt`（玩家值全文），页面不再碰网络；
    - **权威端（单机/主机）**：读请求文件 → 校验 → `DamageValues.ApplyChanges` + `ApplyAll`（状态文件由既有流程写，含 `applied.*`）→ 广播 + 差分聊天公告；
    - **纯客户端**：读请求文件 → `DamageNet.SendSet`；并每 5 秒 `SendGet` 拉状态，把服务器下发的状态写进本机 `TouhouDamageState.txt`（**剔除 `applied.*`**，只作显示；防止污染客户端自己以后的单机/开服归一化），并附 `canedit=` / `denied=`（10 秒新鲜度）供页面做只读态与拒绝提示。
  - 消息（`DamageNet`，反射收发照 BondNet）：`damage_cfgget`（C→S 拉状态）、`damage_cfgset`（C→S 提交）、`damage_cfgstate`（S→全体）、`damage_cfgstatep`（S→单个，附 can_edit）、`damage_denied`（S→单个）。
  - 权限：服务端 `Client.HasPermission(ConsoleCommands)`，并按 `OwnerConnection` 放行服主（反射取属性，兼容双端程序集）。
  - 校验：`DamageValues.TryParseChanges`（已知分组 + 轴合法性 + 范围：伤害/防御 0~10、穿甲 add −1~1 / multiply 0~10），非法整单拒绝并定向回原因。
  - 聊天公告：`DamageChat.Broadcast` → 反射调 `GameServer.SendChatMessage(text, null, null, null, 0, 0)`（专服/主机都走这条）；单机走 `GameSession.CrewManager.AddSinglePlayerChatMessage`；两条路都不通时至少写控制台日志。命令 `damage_set/reset/lv` 同样「快照 → 差分 → 公告」。
  - 覆盖所有改动来源：设置页、控制台命令、手改配置文件（后两者署名为主机角色名 / 服务器名；远程提交署名发送者）。
- **部署要求**：LuaCs 只在**服务器启动时**加载脚本/编译 C#，更新必须**重启服务器**；服务器是否加载了新版看 C# 日志 `[伤害] 伤害设置插件已加载（应用器 + 联机传输）`。
- 尚未做（如需再说）：跨端数值下发不做增量（每次全量约 4 KB）；客户端拉状态固定 5 秒节奏（打开页面最坏等 5 秒才刷新）。

## 12. 实现踩坑记录

1. **Affliction 双强度字段（2026-10-05，实际伤害不变的真凶）**：`Affliction` 有 `_strength`（属性 `Strength`）与 `_nonClampedStrength`（属性 `NonClampedStrength`）。伤害结算路径读的是 **NonClampedStrength**（`Limb.AddDamage` 攻击倍率≈1 时 `SetStrength(NonClampedStrength)`；`CreateMultiplied` 也用它乘）；而 `Strength` 属性 setter 只在 `_nonClampedStrength < 0`（未初始化）时同步它、**之后永不再更新**。写 `Strength` 会让探针（读 Strength）显示正确但实际伤害停在首次打补丁的倍率。**修复：应用器一律用 `SetStrength(value)`**（官方同款，双字段同写）；探针已加 `⚠NonClamped` 回归哨兵。
2. **LuaCs 命令参数形状**：命令回调收到的是 `object[]`，实参包在 `string[]` 里（`args[0] is string[]`）。所有命令走 `CommandArgs()` 兼容两种形状。
3. **分组归属要看清**：`damage_probe` 第一行就是物品所属组——设置组与物品组不一致时"改了没反应"是预期行为（专属 159 件 vs 泛用 76 件，清单见 `Config/damage_settings.xml`）。
4. **联机必须服务端单点写配置**：非权威端 C# 不应用任何数值，所以任何端（含主机 UI）都只写 `TouhouDamageRequest.txt`，由 C# 桥接按权威性处理：权威端本地应用 / 客户端发服务器，服务端校验权限后写自己机器的 `TouhouDamageConfig.txt`。
5. **联机客户端镜像状态文件必须剔除 `applied.*`**：`applied.*` 是权威端 C# 的归一变基（reloadlua 用除法归一）；客户端只做显示（`DamageDisplay.StrippedStateText()` 剥离后 + `canedit=`/`denied=` 落盘），绝不能把服务器记录写进自己的归一化底数，否则自己以后的单机/开服会算错伤害。
6. **权限判定细节（C#）**：`Client.HasPermission` 只是 `Permissions.HasFlag`（无服主特判）→ 服主靠建服时被授予的 `ClientPermissions.All`；`DamageNet.HasPermission` 里额外反射取 `OwnerConnection` 兜底放行。
7. **聊天广播写法（C#）**：优先反射调 `GameServer.SendChatMessage(text, ChatMessageType.Server, null, null, 0, 0)`（参数枚举按运行时类型构造，避开双端程序集类型不一致）；单机走 `GameSession.CrewManager.AddSinglePlayerChatMessage`；都失败至少写控制台。
8. **删除的旧件**：`Lua/Scripts/Server/Touhou_Damage_Settings.lua`（Lua 服务端模块）与 `_dev/dmgtest`（MoonSharp 打桩回归）随 C# 方案一并删除；`TLE_DMG_*` 消息名不再存在，现行消息为 `damage_cfgget/cfgset/cfgstate/cfgstatep/denied`。
9. **中性 = 完全不写（2026-10-05 按作者口径收紧）**：
   - 设置页穿甲模式切换落到**中性值**（加算 0 / 乘算 ×1），不再自动填 0.05 / 1.25——点模式按钮本身不会偷偷改数值。
   - C# 应用器：**本次与上次都是中性**时一个字都不写。穿甲连 `0~1 封顶` 都不做（模组内容里存在 `penetration="-0.1"`、`-0.01"` 这类负值与效果运行期改动，替游戏封顶/同步就是改了数值）；防御与 affliction 同样跳过（affliction 的 `SetStrength` 会顺带同步 `_nonClampedStrength`，中性时不该替游戏同步）。判断依据是状态文件里的 `applied.*` 记录：从非中性回退到中性时仍会写回底值。

13. **运行时自动收录（2026-10-06，作者需求"不用一直更新清单"）**：`DamageConfig.AutoCollect()` 在每次启动（插件加载/巡回开始，内容未就绪会自动延后重试）遍历**已加载的 ItemPrefab**：
    - 只看 `BasePrefab.ContentPackage` 名字含「东方」的物品（东方包对原版物品的 Override 不算，避免把原版武器纳管）；
    - "可补强"判定：有武器组件（Attack/Projectile/MeleeWeapon/RangedWeapon）**或**引用了白名单伤害类型的 affliction（按 `AfflictionPrefab` 判类型）——医疗/涂装类会被排除；
    - 归类：有 `damageModifier` → 凭依武装（id 前缀 Touhou_Hyouibana_Armor）/ 潜水服（id 或路径含 diving）/ 头饰（其它防护装束）；有 Turret 元素或 `turretammosource` 标签 → 舰炮，并顺着 SpawnItem/Containable 引用收弹体闭包（只跟东方包物品）；其余 → 专属；
    - 显式清单里的 id 不动（显式优先）；日志/`damage_list` 会打印 `自动收录：东方包 N 个 / 见过 X 件 / 新增 Y 件（…）`；
    - 会话内只扫一次；`damage_rescan` 强制重扫（新增/更新模组后不用重启）。
14. **单件物品单独调整 `damage_item`（2026-10-06，作者需求"单个射弹的倍率"）**：倍率体系本来是"按组"的；要让某一发子弹单独调，既可以让它单开一组，也可以直接用命令：
    - `damage_item <物品id> damage <倍率>` / `damage_item <物品id> pen <add:0.05|multiply:1.25>`：给这一件物品单独设值，**不再用所属分组的倍率**（同一 prefab 的所有实例一起变）；
    - `damage_item <物品id> clear` 取消；`damage_item list` 列出全部单独调整；
    - 持久化在同目录 `TouhouDamageItems.txt`（手改该文件也会被每秒轮询热加载）；归一基记在状态文件 `applied.item.<id>.*`；
    - 应用器按物品解析生效倍率（`ApplyItem` 里解析后供三个应用函数读），设置页与 `damage_list` 会列出这些调整，`damage_probe` 会显示"单件调整生效"；
    - 前提：物品必须在某个分组里（否则提示先加组）；防具不支持（只支持 damage/pen）。
