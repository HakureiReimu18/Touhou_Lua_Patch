# 探索海图仪（Touhou_ExploredMap）

潜渊症模组：根据玩家走过的路线与声呐扫描的航道，把"已探索区域海图"实时绘制到一个手持屏幕物品的界面上。

## 功能

- **手持海图仪**：新物品 `Touhou_ExploredMap`（装备/潜水分类，可购买、可合成、可分解），装入电池后工作。
- **已探索地图**：整个关卡划分为 25 m 网格（256×128，覆盖 6.4 km × 3.2 km），单元分为未知/开阔水域/岩壁三态。
- **四种探索来源**：
  1. 肉身视野：玩家周围 15 m 持续标记；
  2. 手持海图仪（通电）：玩家周围 60 m 每 1/3 秒标记；
  3. 潜艇被动声呐（有通电 Sonar）：潜艇周围 80 m 每秒标记；
  4. 主动声呐（任一 Sonar 处于 Active 模式）：潜艇周围 150 m 每 5 秒脉冲标记。
- **航线记录**：本地玩家移动超过 2 m 记一个点，上限 6000 点（超出自动抽稀）。
- **两种显示**：
  - 设备表面小屏（世界中实时绘制，丢在地上也看得到）；
  - 手持时右上角 HUD 大图面板：海图 + 航线 + 玩家/潜艇/前哨站标记 + 坐标读数。

## 安装

本功能已并入 **东方潜渊行动组Lua补丁** 模组（2026-08 合并），启用该模组即可获得，无需单独安装。
依赖游戏内置 LuaCs（C# 支持），无需其他前置模组。
源码位置：`Items/ExploredMap.xml` + `CSharp/Client/ExploredMap*.cs` + `CSharp/Shared/ExploredMapComponent_Shared.cs`。

## 测试步骤

1. 单人开一局战役或任务，合成/购买或直接控制台 `spawnitem Touhou_ExploredMap inventory` 获取设备。
2. 装入一块电池（mobilebattery），拿在手上 → 右上角出现海图面板。
3. 游出潜艇转一圈，确认肉身/手持扫描把周围区域标记为蓝色（开阔）与棕色（岩壁），青色线为航线。
4. 回潜艇开主动声呐 ping，确认潜艇周围出现大范围脉冲标记。
5. 把设备放在地上/丢地上，确认设备表面小屏仍在绘制。

## 参数调整

| 参数 | 位置 | 默认 |
|---|---|---|
| 网格尺寸 / 覆盖范围 | `ExploredMapTracker.cs` 顶部常量 | 256×128 / 25 m 每格 |
| 肉身视野半径 | `SelfRevealRadius` | 15 m |
| 潜艇被动/主动声呐半径 | `SubPassiveRadius` / `SubPingRadius` | 80 m / 150 m |
| 手持扫描半径 | XML `ScanRange` 属性 | 60 m |
| 设备屏幕贴图占比 | XML `ScreenScale` 属性 | 0.9 |
| 航线上限 | `MaxPathPoints` | 6000 点 |

## 设计决策记录

- **采用自定义 ItemComponent + IDrawableComponent**：社区模组（TSM 视频屏）已验证 LuaCs 支持 C# 自定义组件类，XML 元素名即类名，服务端也能解析。
- **采用网格化战争迷雾而非复刻原版声呐绘制**：原版声呐的洞壁渲染路径（NavTerminal/SonarMonitor 内部）签名未逐一验证，网格化 + `Level.GetCells`/`ExtraWalls.IsPointInside` 采样分类的方案全部基于已验证 API，且天然适配"持久化探索"语义。
- **主动声呐模式经反射读取 `Sonar.CurrentMode`**：规避版本间枚举签名差异，失败时静默降级为仅被动扫描。
- **组件继承 Powered**：电池供电复用原版手持声呐的 `OnContaining → Voltage=1.0` 模式，无需自造供电逻辑。
- **被拒绝：Tags/字典做多人同步**：探索位图是高频增量二进制数据，Tags 方案不可行；多人同步需要自定义网络消息 + 增量包 + late-join 快照，v1 明确不做。
- **被拒绝：存档持久化**：需要挂接存档序列化管线，v1 明确不做，换关卡即重置。

## 离线编译检查（tools/）

`tools/compile-check.ps1` 用本机 .NET 8 运行时驱动 Roslyn 官方编译器（`tools/nct`），
以友元程序集名 `InternalsAwareAssembly` 引用游戏程序集，对客户端（带 `CLIENT` 符号）与服务端
分别做语义级编译验证——与 LuaCs 运行时编译行为一致，改代码后跑一遍即可在不开游戏的情况下排错：

```
powershell -NoProfile -ExecutionPolicy Bypass -File tools\compile-check.ps1
```

注意：`tools/` 目录（约 16 MB）仅为开发工具，**不要打包进创意工坊发布**；
发布时排除 tools/ 与 Docs/ 即可。该脚本现在面向整个补丁模组（自动收集 CSharp 下全部源码，
客户端 = Client+Shared，服务端 = Server+Shared），改动任何 C# 文件后都可直接跑。
请保留 `compile-check.ps1` 的 UTF-8 BOM
（编辑器保存时选 "UTF-8 with BOM"，否则 PowerShell 5.1 会因中文注释解析失败）。

## 设计决策记录（修订）

- **追踪节拍采用 `Level.Update` Harmony 后置补丁**：初版方案用 `GameMain.LuaCs.Hook.Add("think", …)`，
  编译验证发现该 API 在 1.12.7.0 已移除（CS0117）。`Level.Update` 补丁点经社区模组（Capture/ShowPerf）
  实机验证，且只在关卡激活时被调用，语义更贴合。
- **编译检查发现的版本事实**（离线编译验证的价值）：
  - 游戏 internal API 通过 `InternalsVisibleTo("InternalsAwareAssembly")` 向模组开放，LuaCs 编译模组即用此程序集名；
  - Xna 基础类型（Vector2/Color/Rectangle）在本版本独立拆分到 `XNATypes.dll`，不在 MonoGame.Framework 主程序集中。

## 已知限制

- 多人联机时每个客户端各自构建本地海图，**不同步**（服务端权威 + 增量同步留作 v2）。
- 海图**不随存档持久化**，重开回合/换关卡即重置。
- 电池耗尽（耐久归零）后 Voltage 信号可能仍然保持（原版手持声呐同款行为），此时设备仍会扫描；后续可加 Condition 判定。
- 首次在新机器/新版本启用时若 LuaCs 报编译错误，看游戏控制台日志定位；所有 API 接触点均已在注释标注出处。
