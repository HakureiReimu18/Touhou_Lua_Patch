# 通用射弹追踪（任意实体射弹）可行方案

> 实施路线已确定为 **C#（Shared 程序集）**。动机：多人环境每秒数十发射弹属常态，
> 追踪是持续检测型系统，MoonSharp 解释执行 + Lua↔C# 互操作开销在该负载下不可忽视；
> 项目已有现成的 C# 插件基础设施（词缀/羁绊系统），无需新增任何配置。

## 1. 背景与现状

现有"君王"（Touhou_Monarch）的追踪实现在 `Lua/Scripts/Server/Touhou_Monarch.lua`（已迁移到 C#，见下），核心机制：

- `Hook.Patch("Barotrauma.Items.Components.Projectile", "Shoot", ...)` 捕获射弹发射事件；
- 射弹登记进 `active_rounds` 列表；
- `think` 钩子每帧用 `round.body.ApplyLinearImpulse` 转向（目标方向单位向量 − 速度方向单位向量，乘以转向力度），另有最低速度维持；
- 目标来源：定位鱼叉实体位置，或射手鼠标瞄准方向 30° 半锥角、2000 模拟单位内的最近敌人（每帧全扫 `Character.CharacterList`）。

该实现只认 `Touhou_Monarch_Round01/02` 两个 prefab，硬编码、单武器专用。**君王现已完整迁移进插件**
（`CSharp/Shared/MonarchHoming.cs`，命名空间 `Touhou.Homing`，数值与判定顺序照抄 Lua 版），
Lua 脚本 `Lua/Scripts/Server/Touhou_Monarch.lua` 停止加载（文件留在磁盘作回退保险，见 `Lua/Autorun/init.lua`）。
迁移动机就是下面 §4.6 说的引擎坑：通用系统同样会中招，于是两边共用同一套"引导释放 + 穿身补伤"。
两边同时转向会叠加，所以任何时刻只能留一边。
君王侧另有一条自己独有的逻辑：**鱼叉插住的生物死亡后，追踪弹自动放弃这根鱼叉、转回鼠标引导去找新目标**
（复用穿身补伤那套受害者反查；插在墙/结构上解析不出角色的不算）。通用系统不需要这条——它本来就有
"目标死亡/消失 → 丢弃并重捕"。

## 2. 目标

推广为通用机制：**任意 `hitscan=false` 的实体射弹**（手持武器射弹、炮塔射弹均可）按配置：

- 在射弹**当前飞行方向**的锥角内；
- 在最大距离内；
- 捕获并追踪敌方角色；
- 多人环境每秒数十发、场上数十至上百活跃射弹时性能可忽略。

## 3. 技术可行性（C# 路径）

> **API 已对本机游戏程序集做反射验证**（dnlib 转储，2026-09；GitHub 源码与游戏版本有出入，以转储为准）：
> - `Projectile.Shoot(Character user, Vector2 weaponPos, Vector2 spawnPos, float rotation, List<Body> ignoredBodies, bool createNetworkEvent, float damageMultiplier, float launchImpulseModifier)`；
> - hitscan 属性名是 **`Hitscan`**（小写 s），非 GitHub 源码的 `HitScan`；
> - `Projectile.Launcher`（公共字段 `Item`，发射它的武器/炮塔）、`Projectile.User`/`Attacker` 均存在；
> - `GameServer` 在 **DedicatedServer.dll**（不在 Barotrauma.dll），tick 挂点须 `#if SERVER` 编译期分流 + AppDomain 反射兜底，不能照抄 `RagdollScaleTickPatch` 的 `typeof(GameMain).Assembly.GetType`（在专用服务器上会 miss）；
> - `Timing.TotalTime` 为公共静态字段；`Item.body`、`Character.CharacterList`、`CursorWorldPosition`、`TeamID`、`IsBot` 均存在；
> - `Character`/`Item`/`Projectile` 均为 internal，但游戏模组编译器对模组程序集开了 InternalsVisibleTo（现有 Mod.cs 直接引用这些类型可编译），直接用 `typeof()` 打补丁无碍；
> - 日志类是 `Barotrauma.LuaCsLogger`（注意不在 `Barotrauma.LuaCs` 命名空间）。

1. **发射入口有两个**（IL 扫描本机游戏程序集验证，2026-10）：`Projectile.Shoot` 全游戏仅三处调用——`RangedWeapon.Use`（手持武器）、`StatusEffect.SpawnItem`、`Projectile.ClientEventRead`（客户端网络事件）。**炮塔完全绕过 Shoot**，路径是 `Turret.Use → TryLaunch → Turret.Launch(Item projectile, Character user, float?, float)`，由 `Launch` 手工完成 SetTransform + LinearVelocity + `Projectile.User/Attacker` 赋值。因此需要两个 postfix：`Projectile.Shoot` + `Turret.Launch`（参数名未验证，用位置绑定 `__0`=射弹 Item、`__1`=射手）。
2. **hitscan 过滤无悬念**：C# 直接访问 `Projectile.Hitscan` 属性（名称已反射验证），不存在 Lua 暴露性问题（原 Lua 路线的头号风险项消失）。
3. **物理操控通用**：射弹 Item 的 `body.ApplyLinearImpulse` 与武器无关，C# 调用无互操作开销。
4. **服务端权威**：物理由服务端模拟。运行时守卫沿用项目惯例：
   `GameMain.NetworkMember == null || GameMain.NetworkMember.IsServer`
   （见 `CSharp/Shared/BondPlugin.cs:91`）。Shared 程序集双端编译，客户端上下文直接跳过追踪逻辑。
5. **每帧挂点有先例**：客户端/单人 `GameMain.Update`、专用服务器 `GameServer.Update` 的 Harmony postfix 模式已在 `RagdollScaleTickPatch`（`CSharp/Shared/RagdollScalePatches.cs:782`）验证，含 `Timing.TotalTime` 节流写法。
6. **插件组织有先例**：新建独立 `IAssemblyPlugin`（仿 `BondPlugin`，`CSharp/Shared/BondPlugin.cs:13`），独立 Harmony 实例、只 Patch 本命名空间的类、`OnLoadCompleted` 里 `UnpatchSelf()` 防 reloadlua 堆叠。

## 4. 方案设计

### 4.1 文件与结构

新文件 `CSharp/Shared/HomingProjectiles.cs`，命名空间 `Touhou.Homing`：

```
HomingPlugin : IAssemblyPlugin        // 仿 BondPlugin：Initialize/OnLoadCompleted/Dispose
HomingConfig                          // 静态配置表 + 可选 XML 重载
HomingShootPatch                      // Harmony postfix on Projectile.Shoot（手持武器/状态效果）
HomingTurretPatch                     // Harmony postfix on Turret.Launch（炮塔；炮塔不走 Shoot，见 §3.1）
HomingTickPatch                       // Harmony postfix on GameMain.Update / GameServer.Update
HomingTracker                         // 活跃射弹列表、目标捕获、转向（全部静态，零实例化）
HomingFallbackHit                     // 穿身补伤的共用善后：解析受害者 + 补刀 + 移除（见 §4.6）
```

君王迁移版在另一个文件 `CSharp/Shared/MonarchHoming.cs`（同命名空间，同一个插件实例）：

```
MonarchTracker                        // 君王 Round01/02 的登记、鱼叉/鼠标引导、转向（规格照抄 Lua 版）
                                      // 另有：引导释放 + 穿身补伤（§4.6）、鱼叉目标死亡 → 转鼠标引导
MonarchShootPatch                     // Harmony postfix on Projectile.Shoot（只认 Touhou_Monarch_Round01/02）
```

配置来源：`Config/homing_config.xml`（仿 `bond_config.xml` 先例），`roundStart` 自动重载 +
控制台命令 `homing_reload` 即时重载（改完 XML 游戏内敲命令即生效，连巡回都不用重开；
命令注册有 `BondMatch.RegisterCommands` 先例）。

```xml
<HomingConfig enabled="true" maxActive="128" scansPerFrame="8">
  <!-- 缺省值模板：任何参数不写就回落到这里，再回落到代码常量 -->
  <Default range="2000" coneDeg="45" mode="velocity" steering="5"
           minSpeed="0" accel="0.25" acquireInterval="0.2" lockOn="true" maxLifetime="10"
           armDist="200" armTime="2" releaseDist="300" passHitDist="100" trackInsideSub="true"/>
  <!-- 最小条目只写 id，其余全用缺省；"是否追踪" = 条目存在与否 -->
  <Projectile id="coilgunbolt"/>
  <Projectile id="Touhou_Onmyo_Ball_Bullet" mode="mouse" coneDeg="30"/>
  <!-- 一族弹药用前缀匹配，一条规则覆盖 -->
  <Projectile idPrefix="railgun" coneDeg="15" steering="3"/>
</HomingConfig>
```

> 别登记 `Touhou_Monarch_Round01/02`：君王追踪已内置在插件里（`MonarchHoming.cs`），
> 再登记一次会和内置逻辑叠加成双重转向。

匹配顺序：精确 `id` → `idPrefix` → 不匹配（不追踪）。参数解析逐级回落：
条目属性 → `Default` → 代码常量（一个通用 `GetAttrOr` 辅助函数）。
角度在配置里用角度制，加载时转 `AcquireConeCos`；未知属性打警告后忽略，schema 向前兼容。

`mode` 枚举：`velocity`（锥心/原点/距离锚在射弹自身，默认）/ `mouse`（锥心/原点/距离锚在射手，
君王语义——射弹飞远后仍可按当前瞄准方向重新捕获；
沿用君王教训：必须 `CursorWorldPosition`，`CursorPosition` 在舱内是潜艇相对坐标）。

预留旋钮（schema 已容纳，按需实现）：`targetFilter="all|human|monster"`、比例导引增益等。

```csharp
public enum HomingMode { Velocity, Mouse }

public class HomingParams
{
    public HomingMode Mode;
    public float AcquireConeCos;     // 捕获半锥角的 cos 预存（见 §5 点积判定）
    public float AcquireRangeSqr;    // 捕获距离的平方预存
    public float SteeringMagnitude;  // 转向力度
    public float MinimumSpeed;       // 最低速度维持（0 = 不维持）
    public float AccelerationMagnitude;
    public float AcquireInterval;    // 目标重捕获间隔（秒，Timing.TotalTime 计）
    public bool  LockOn;             // true = 锁定后不换目标
    public float MaxLifetime;        // 超时强制移出
    public float ReleaseDist;        // 引导释放距离：进到这么近就不再转向（0 = 一直追踪，见 §4.6）
    public float PassHitDist;        // 穿身补伤半径：飞过最近点时这么近以内算穿身，补一刀（见 §4.6）
    public bool  TrackInsideSub;     // 是否允许追踪潜艇舱室内部的目标；false = 登船敌人不再把弹"勾"回自家船体
}
```

### 4.2 登记流程

```
发射入口 postfix（C# 内直接访问，无互操作）：
  手持武器/状态效果 → Projectile.Shoot；炮塔 → Turret.Launch（见 §3.1）
  └─ identifier 查 Dictionary（未命中 = 一次哈希查找，零后续开销）
  └─ Hitscan → true 直接返回（炮塔路径由 GetComponent&lt;Projectile&gt;() 取组件）
  └─ 延迟登记：射弹出炮口帧速度方向未稳定，用“首帧 tick 时再激活”标记位
       （比 Lua 的 Timer.Wait 更省：不进计时器队列，tick 里顺手处理）
  └─ 插入活跃列表（预分配容量的 List<Entry>，swap-remove）
```

### 4.3 目标捕获

锥心由配置 `mode` 决定（见 §4.1）：`velocity` = 射弹自身速度方向（炮塔/弹幕默认）；
`mouse` = 射手→鼠标的世界方向（君王式引导）。两种模式共用同一套扫描逻辑，只差锥心向量来源：

- 遍历 `Character.CharacterList`（直接引用缓存，不用每帧重新取属性）；
- 过滤：`Removed` / `IsDead` / 射手本人 / 同队 / （`trackInsideSub=false` 时）位于潜艇舱室内部的目标
  （判定用 `CurrentHull.Submarine`：登船敌人会被排除，在艇壳外扒着或在水里的目标不算"艇内"，照常追踪；已锁定目标进艇同样立即脱锁）；
- 粗筛：`Vector2.DistanceSquared` 对 `AcquireRangeSqr`（velocity 模式原点在射弹；**mouse 模式原点与距离锚在射手**——君王 Lua 语义，射弹飞远后仍可按当前瞄准方向重新捕获）；
- 锥角判定：**点积**（见 §5），取锥内点积最大（= 夹角最小）者；
- 敌对判定沿用 `TeamID != shooter.TeamID`；`user == null`（AI 炮塔等边界）的回退规则见 §6。

### 4.4 追踪与转向

每帧 tick（仅权威端）：

- 遍历活跃列表（反向 for + swap-remove）：`Removed` / 超 `MaxLifetime` → 移除；
- 到捕获时刻 → 扫描目标；`LockOn` 模式下只校验已锁目标（Removed/IsDead/超距），不重扫；
- 引导发射：距离 > `ReleaseDist` 才转向（单位向量差 × `SteeringMagnitude` 冲量；低速时补加速冲量，君王同款数学），
  进到 `ReleaseDist` 以内即标记释放，此后不再施加任何冲量；
- 每帧记录对当前目标的最小距离，飞过最近点时判定穿身补伤（见 §4.6）。

### 4.5 终止条件

射弹 `Removed`（命中/消失）、超 `MaxLifetime`、穿身补伤善后（§4.6）。

### 4.6 引导释放 + 穿身补伤（引擎坑）

**问题**：转向是每帧恒定力，弹接近目标后不是撞上去，而是绕着目标转圈。伤害完全依赖引擎碰撞，
而引擎在若干已知情况下登记不上命中（穿 hull 后坐标系失配——世界坐标看着重合、物理坐标差几百单位；
碰撞被先前命中关掉导致"幽灵弹"等），于是弹永久绕圈、零伤害。旧版那套"失配检测 → 5 米内补刀"在这个
场景里还帮了倒忙：目标是鱼叉（Item）时解析不出受害者，结果只是**静默移除**，看起来就是"没伤害"。

**新模型（`Config` 的 `releaseDist` / `passHitDist`，通用追踪与君王迁移版共用同一套）**：

1. **引导释放**：只在距离 > `releaseDist`（默认 300 ≈ 3 米）时转向；一旦 ≤ `releaseDist` 就标记"已释放"，
   此后永久弹道飞行，不再回头、不再绕圈。`releaseDist = 0` 关闭释放，退回旧的一直追踪行为（逃生舱）。
2. **穿身补伤兜底**：每个条目记录对**当前目标**的最小距离 `minDist`（目标实体变化时重置）。
   当弹"飞过了最近点"（本帧距离 > `minDist`）且 `minDist <= passHitDist`（默认 100 ≈ 1 米）且弹未被移除、
   `HiddenInGame == false` 时：
   - 解析受害者：目标本身是 `Character` → 用它；目标是鱼叉（`Item`）→
     `harpoon.GetComponent<Projectile>()?.StickTarget?.UserData as Limb` → `limb.character`；解析不出就只移除不补伤；
   - 命中走引擎伤害入口（`DoDamageToLimb(attacker, limb, pos, 1.0f, playSound: false)`，优先躯干、
     否则第一个未断肢体），**随后完整复刻引擎 `HandleProjectileCollision` 的命中善后**：
     `OnSuccess/OnFailure`（掷骰与引擎一致：`Rand.Range(0, 0.5, RandSync.Unsynced) > DegreeOfSuccess`）
     + `OnImpact` 两组状态效果（散射生成、爆炸、音效、粒子都挂在这里），并以
     `Item.ApplyStatusEffectEventData` 向客户端广播；最后 `Entity.Spawner?.AddItemToRemoveQueue(item)`
     移除该弹（若效果的 `<Remove/>` 已移除则跳过），并从追踪列表删条目。
     未复刻引擎对"被击中肢体自身 attack"的反击效果（怪物受击反应类），当前需求不涉及。
   - **位置对齐（关键，2026-10 修，同月二次收紧）**：引擎路径里弹停在命中接触点（目标表面），兜底路径弹已飞过目标。
     若直接在当前位置执行效果，`SpawnItem spawnposition="This"` 会把溅射子弹生成在目标体内/身后的
     几何里，出生即碰撞触发自身 `OnImpact → Condition-100 → OnBroken → Remove` 而"瞬间消失"
     （实测 `Touhou_Nue_Danmaku_Chimera_Bolt` 的 8 枚溅射弹）。因此补刀前先把弹挪回"可见命中点"：
     以**被击肢体自身**为锚点，沿来向退到表面外 0.15 米（`GetMaxExtent()` + 0.15，无保底——
     首版用"角色中心 + 1 米保底"会把生成点放得偏外，溅射弹会先飞一段空档才命中，与引擎路径
     "贴着怪物命中"的观感不一致），用 `WorldPosition` 差值（帧无关：
     `WorldPosition = 帧偏移 + ToDisplayUnits(SimPosition)`）换算 SimPosition 增量后
     `SetTransform`；随后 `FarseerBody.Enabled = false` 冻结刚体（复刻引擎 RemoveOnHit 处置），
     防止挪位后残余速度在移除生效前再次撞出命中造成双触发。0.15 米在弹速下约 3 毫秒（远小于一帧），
     朝怪物飞的溅射弹生成后一帧内即命中消失，观感等同引擎路径。
3. **防重（关键）**：
   - `HiddenInGame` 由引擎命中处理置 true（`removePending`），置位后一律跳过兜底；
   - 穿透弹（`removeonhit=false`）`HiddenInGame` 永不置位，由 `HomingFallbackHit.EngineAlreadyHit()`
     检查 `Projectile.Hits` 里是否已出现受害者的肢体来兜底，两重判断合起来**绝不会双倍伤害/双倍效果**。
   - 真实打偏（`minDist > passHitDist`）也不触发——**打偏仍然是打偏**，弹自己飞走。

语义上这条兜底同时覆盖了旧的坐标系失配场景：失配弹会被引导到目标的世界坐标附近、从目标身上"穿过"
（世界坐标路径重合）→ 兜底补伤。所以旧的失配检测/计时那套已经删掉，不再需要。

**代码落点**：判定在 `HomingTracker.Tick()` / `MonarchTracker.Tick()` 里（各条目自带 `MinDist`/`Released`），
补刀与移除共用 `HomingFallbackHit.Apply()`。

**君王独有：鱼叉目标死亡就换人**。Round02 追的可能是鱼叉，鱼叉插着的生物死了以后没必要再追那根插在尸体上的
鱼叉。`MonarchTracker` 因此多两条：发射登记时若鱼叉插住的生物已死，就当"没有鱼叉"，这发直接走鼠标引导，
并把 `lastHarpoon` 里那条清掉；追踪中每帧检查一次，死了就 `Harpoon = null`（同一帧落入鼠标引导分支找新目标），
并把该弹的 `Released`/`MinDist` 一起清掉——否则已经释放的弹不会转向新目标，`MinDist` 留着旧目标的最小距离
还会误判穿身补伤。鱼叉**被移除**（`Removed`）走的还是老路：整条停止追踪。

## 5. 性能设计（C# 版）

多人每秒数十发、射弹存活 1~2 秒 → 稳态活跃 50~150 枚。C# 路径下各热点的处理：

| 措施 | 说明 |
|---|---|
| 锥角点积判定 | `Vector2.Dot(速度单位向量, 目标偏移/距离) > AcquireConeCos`，全程无 atan2、无开方（粗筛后只需一次开方取单位向量） |
| 平方距离粗筛 | 先 `DistanceSquared` 比 `AcquireRangeSqr`，绝大多数候选在此被挡 |
| 捕获节流 + 错峰 | 每枚射弹 `nextAcquire = 发射时刻 + interval × (1 + 列表索引%8/8f)` 抖动，避免同帧集体扫描 |
| LockOn 稳态零扫描 | 锁定后每帧只做 3 个布尔/距离校验 |
| 扫描轮询上限 | 每帧最多处理 K 个到期扫描（如 K=8），超出的顺延到下一帧——把尖峰摊平成固定上限 |
| Shoot 入口零开销 | 非配置射弹 = 一次 Dictionary 查找；hitscan = 一个字段判断 |
| 活跃列表硬上限 | 如 128，超出拒登新弹（不淘汰旧弹，避免抖动） |
| 释放即停手 | 进到 `releaseDist` 以内后连转向计算都省了，只剩一次距离比较（成本比一直转向还低） |
| 零分配热循环 | 不用 LINQ、不用 foreach 造枚举器（`Character.CharacterList` 用 for 索引遍历）、Entry 用引用类型复用槽位 |
| 零互操作 | 全程原生 C# 访问 `body`、`WorldPosition`、`ApplyLinearImpulse`，无 MoonSharp 边界 |

**成本估算**（100 活跃射弹、60 角色）：

- 转向：100 × （几次 Vector2 运算 + 一次冲量调用）/帧 ≈ 数千次浮点运算/帧，纳秒级单价，可忽略；
- 扫描：轮询上限 8 个/帧 × 60 候选 × （1 次平方距离 + 偶发点积） ≈ 500 次廉价比较/帧，可忽略；
- 对比 Lua 路线：同等逻辑在 MoonSharp 下单价高 1~2 个数量级，且每次属性访问跨互操作边界——这正是选 C# 的理由。

节流设计仍然保留（不是性能所迫，而是行为所需：锁定/降频让弹道弧线稳定可读，每帧换目标的追踪看起来会"抽搐"）。

**内置自测（2026-10 加）**：`HomingProfiler`（`HomingProjectiles.cs` 末尾）——`HomingProfiler.Enabled = true` 时，
每 5 秒汇总一条 `[perf]` 日志：tick 平均/峰值耗时、累计耗时、活跃追踪数（通用+君王）、周期内角色表扫描次数。
计时本体（每帧两次 `Stopwatch.GetTimestamp`）只在自测开关打开时执行，正常游玩零开销。
排查性能时：开自测开关 → 打一场多炮塔齐射/弹幕战 → 看 `[perf]` 行的 µs/帧 即可；关闭后无任何输出。
（同期清理：诊断用的探针日志与逐事件 dbg 日志已整体移除，只保留 `HomingLog.Warn` 与
`HomingLog.Verbose` 控制的低频加载信息。）

9. **穿身补伤的边界**：兜底只在"弹确实从目标身上穿过"（最近距离 ≤ `passHitDist`）且引擎没登记命中时才补刀；

## 8. 其他模组兼容方案（已实现）

三个层级，按接入成本从低到高；同一射弹的生效优先级反过来：**运行时注册 > 配置文件精确 id > 配置文件 idPrefix > prefab tag**。

### 8.1 prefab tag（零配置，一行 XML）

其他模组在自己的射弹物品 XML 里加 tag 即可，无需任何配置文件：

```xml
<Item name="..." identifier="my_mod_bolt" tags="touhou_homing">   <!-- velocity 模式，默认参数 -->
<Item name="..." identifier="my_mod_bolt2" tags="touhou_homing_mouse">  <!-- mouse 模式 -->
```

参数用当前默认值（受各包配置文件 `<Default>` 层叠影响）。适合"能追踪就行"的弹药。

### 8.2 各自包内的配置文件（全参数，无代码）

其他模组在**自己的模组包**里放 `Config/homing_config.xml`（与本模组同 schema），本系统加载时扫描**所有启用内容包**（`ContentPackageManager.RegularPackages`）并合并：

- 同 id 条目：加载顺序靠后的包覆盖先前的（创意工坊列表里排后面的赢）；
- `<Default>` 沿加载顺序层叠，每个文件的条目以"层叠后的默认值"为底；
- 本模组自己的配置文件也走同一条扫描路径，无特殊地位。

适合需要调参数的弹药；适合纯内容包（无 C#/Lua）的模组。

### 8.3 运行时 Hook 注册（动态开关）

Lua/C# 模组都可通过全局 Hook 在运行时注册/注销，参数键名与 XML 属性一致：

```lua
-- 在其他模组的 Lua 里（注意在 roundStart 等钩子里调用，Autorun 顶层可能早于本插件加载）
Hook.Add("roundStart", "mymod_homing_reg", function()
    Hook.Call("touhouHomingRegister", "my_mod_bolt", {
        mode = "velocity", coneDeg = 30, range = 2500, steering = 6,
        lockOn = true, acquireInterval = 0.2, maxLifetime = 10,
        minSpeed = 0, accel = 0.25, armDist = 200, armTime = 2,
    })
end)
-- 注销：Hook.Call("touhouHomingUnregister", "my_mod_bolt")
```

运行时注册**优先于**所有配置文件条目，且不受 `homing_reload` 影响（重载文件不会清掉它）。
适合按游戏内状态动态开关追踪（如附魔/升级系统解锁后启用）——本模组未来的"追踪词缀"也走这条路。

## 9. 已知非本系统行为：射弹偶尔"从手部发射"

**现象**：有时实体射弹从玩家手部/躯干附近飞出，而不是武器枪口。

**结论（2026-10 IL 与源码双重验证）**：这是**原版游戏的防卡墙保护**，不是本系统副作用，已决定保持原版行为不修改。

- `RangedWeapon.Use` 传给 `Projectile.Shoot` 的 `weaponPos` 是 `user.AnimController.AimSourceSimPos`（角色瞄准源，手部附近），`spawnPos` 才是枪口（`武器 body.SimPosition + TransformedBarrelPos`）；
- `Projectile.Shoot` 默认 `projectilePos = weaponPos`，然后 `Submarine.PickBody(weaponPos, spawnPos, ...)` 射线检测（CollisionWall | CollisionLevel | CollisionItemBlocking）；
- 射线通畅才改用枪口；**被挡住就在手部附近生成**（或落到手后方 `maxExtent` 处）。

**触发条件**：枪口插进/贴住舱壁、舱门，站在门口，探身贴地形，大俯仰角时射线穿过甲板/天花板，枪口被阻挡物遮挡等。

**若某个武器触发过于频繁**：优先调该武器 XML 的 `barrelpos`（枪口越靠近枪体，手→枪口射线越短），属内容层修复。

**若未来仍想强制枪口生成**（已评估后搁置）：`Shoot` prefix 记录枪口 → `Projectile.Launch` postfix 修正位置，仅对追踪射弹生效的配置开关。风险明确：贴墙时射弹生成在墙体内会立即卡住/吸附，枪口探出薄墙时等效穿墙，需按弹药逐个开关，默认关闭。
